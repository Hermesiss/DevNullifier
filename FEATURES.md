# Предложения по функционалу

Новые возможности поверх текущего AppData Cleaner и Dev Cleaner. Баги и защита от удаления — в `AUDIT.md`, сюда они не дублируются. Порядок внутри раздела — от более полезного к более дорогому.

## Безопасное удаление

Сейчас удаление сразу и навсегда, диалог только предупреждает.

- Корзина вместо прямого `rm`. Кнопка «Удалить навсегда» остаётся отдельно, по умолчанию выключена.
- Список защищённых путей: корень диска, профиль, `userData` приложения, системные каталоги. Пользователь может добавить свои. Совпадение блокирует и скан, и удаление.
- Исключения по маске для обоих клинеров: «не трогать `*/Saved/SaveGames`», «не трогать каталоги с `.gitkeep`». Хранить рядом с сохранёнными путями в `userData`.
- Порог по возрасту и размеру. Прятать или не выбирать папки новее N дней и мельче N мегабайт. Для AppData это отсекает свежий кэш открытых программ, для Dev Cleaner — сегодняшний `target/`.

## Обзор перед удалением

Таблица есть, фильтров нет.

- Поиск по пути и фильтр по категории в обеих таблицах.
- Сортировка уже частично есть у AppData; добавить те же колонки в Dev Cleaner: размер, дата изменения, тип проекта.
- Группировка AppData по приложению: `AppData/Local/Vendor/App/...` сворачивается в одну строку с суммой, внутри — найденные cache/temp.
- «Почему попало в список»: для AppData — какое слово из `KEYWORDS` сработало, для Dev Cleaner — категория и паттерн. Паттерн в данных воркера уже есть, в таблице его нет.
- Открыть каталог в проводнике и копировать путь из строки. Сейчас путь только читается.

## Скан

Полный обход тяжёлый, быстрый скан умеет только перечитать прошлый список.

- Отмена, которая обрывает подсчёт размера, а не ждёт конца текущего каталога. Прогресс: сколько каталогов просмотрено, текущий путь уже есть.
- Параллельный подсчёт размера с лимитом одновременных обходов. Сейчас размер считается строго по очереди.
- Пресеты Dev Cleaner: «только регенерируемое» (`node_modules`, `target`, `__pycache__`, `bin/obj`) и «агрессивное» (текущий набор с `Saved/`, `Library/`, `checkpoints/`). Сейчас все категории включены сразу.
- Свои категории: имя, файлы-детекторы, паттерны кэша. Встроенные оставить в коде, пользовательские — в `userData`. Тот же механизм для своих ключевых слов AppData.
- Глобальные кэши инструментов отдельной группой, не через обход проектов: npm/yarn/pnpm, NuGet, Gradle, pip, Cargo, Hugging Face, Unity пакеты. У них известные пути в профиле, глубокий скан не нужен.
- Продолжать обход внутрь монорепы после найденного проекта. Сейчас вложенные пакеты пропадают. Показывать их как дочерние строки родителя.
- Игнор служебных деревьев при спуске: `.git`, `node_modules` как контейнер зависимостей, `Library` Unity. Иначе скан домашнего каталога на глубине 10 уходит в чужие файлы.

## После очистки

- Журнал операций в `userData`: дата, путь, размер, успех / частично / ошибка. Экспорт в CSV. Нужен, когда что-то снесли и надо вспомнить что.
- Сравнение с прошлым сканом: что выросло, что появилось, сколько освободили в последний раз. Данные прошлого скана уже пишутся в JSON, но только как список путей.
- Если файл занят, показывать процесс, который его держит, и кнопку «повторить». Сейчас такие пути просто `failed` или `partial`.

## Платформа

- На Windows не требовать администратора для очистки своего профиля. Отдельная кнопка «перезапустить с повышением», если скан упёрся в чужой каталог.
- Настройки в одном месте: язык, тема, канал обновлений, корзина, пороги, исключения. Сейчас язык и тема в шапке, канал обновлений — в меню проверки обновлений, остального нет.
- Строка состояния диска: свободно на томе, сколько выбрано к удалению, сколько это в процентах от свободного места.
